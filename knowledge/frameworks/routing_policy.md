# Политика маршрутизации моделей, процессов и инструментов (Routing Policy)

Цель: максимальная точность стратегии при минимальной стоимости и отсутствии галлюцинаций в расчётах.

## 1. Принцип разделения вычислений
| Класс задачи | Исполнитель (Tier) | Инструмент | Запасной путь (Fallback) |
|---|---|---|---|
| Арифметика, юнит-экономика, воронки, размер выборки A/B | `deterministic_python` | `tools/calculators/economics.py` через CLI/MCP | Ручная формула с явным пошаговым выводом |
| Поиск по базе знаний и проверка цитат/секретов | `deterministic_python` | `tools/kb_index.py`, `tools/hooks/validators.py` | Построчный grep по `sources.yaml` |
| Уточнение задачи, извлечение фактов из PDF, генерация гайдов и синтетические интервью | `fast_tier` (экономичная LLM) | `01-task-intake`, `02-research-sources`, `03-synthetic-interview` | Структурированный шаблон + поэтапный ввод |
| Разбор скриншотов, интерфейсов, видео/аудио | `multimodal_reasoning` (только при наличии медиа) | `04-ux-audit` | Текстовый лог экрана + метка `[НЕДОСТАТОК ДАННЫХ]` |
| Генерация >=3 альтернатив, Red-Team критика, сквозной синтез стратегии и пересмотр решений | `reasoning_tier` (старшая LLM) | `06-options-redteam`, `07-strategy-packager`, `08-decision-revision` | Двухпроходная генерация на `fast_tier` (черновик -> чек-лист критика) |

## 2. Правило классификации
Перед началом нетривиального шага агент вызывает `uv run python -m tools.strategist_cli route "<запрос>"` (или MCP `strategist_route`), чтобы зафиксировать выбор процесса, модели и сэкономить бюджет контекста.
